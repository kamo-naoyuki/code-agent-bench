# Claude Code / Codex 接続部分の共通ルール

## 目的

このホストでログイン済みの Claude Code / Codex に、Harbor のテスト用コンテナで問題を解かせる。
新しい API キーを要求せず、GitHub Copilot と同じ問題を解かせて、ツール全体の成績を比較できるようにする。

今回比較するのは「各ツールを、共通のコンテナ操作用ツールだけが使える条件で動かした結果」。
各製品の標準機能をすべて有効にした比較でも、AI モデル単体の比較でもない。

## 既存実装と環境

- 作業場所: `/data/store5/2026/kamo/code_agent_test`
- [copilot_host.py](./copilot_host.py): 動作確認済みの Harbor 外部型 agent。構成の参考にする。
- [sandbox_mcp.py](./sandbox_mcp.py): コンテナ操作用の `bash` を公開する MCP サーバー。
- [env.sh](../env.sh): `source bench/env.sh` で Harbor の環境を設定する。
- [smoke-fix-calc](../../tasks/dev/smoke-fix-calc): 動作確認用の既存タスク。
- Harbor の Python は、`harbor` 実行ファイルのリンク先と同じディレクトリの `python`。システムの Python と異なる。

CLI の導入は確認済み。自動実行で既存ログインが使えるかは未確認。
Copilot のフラグやイベント形式を、そのまま他の CLI に当てはめない。
インストール済み CLI の `--help` と公式資料で確認する。

## 必須条件

1. **ログインはホストに残す。**
   - CLI はホストで動かし、既存の正規ログインを利用する。
   - 認証ファイルやトークンを表示・複製しない。コンテナにも渡さない。
   - ログインが使えなければ、必要な正規のログイン操作を報告して停止する。認証の回避はしない。
2. **評価される AI にホストを操作させない。**
   - コンテナの操作は MCP の `bash` → Harbor の `environment.exec()` だけを通す。
   - ホストのシェル、ファイル読み書き、Web、別 agent、過去セッション参照などを使わせない。
   - ユーザー設定の別 MCP、指示ファイル、メモリも無効化または隔離する。通常のユーザー設定を変更しない。
   - 空の一時作業ディレクトリを使うだけでは不十分。ツールの制限も必要。
   - その制限を CLI が実現できなければ、制限を緩めず、未対応として報告する。
3. **問題と採点を変えない。**
   - AI に渡すのは問題文とコンテナ操作の説明だけ。隠しテストや解答例を渡さない。
   - タスク、コンテナ資源、ネットワーク設定、制限時間、採点は Harbor に従う。
   - 権限拒否・認証失敗・起動失敗を「問題を解けなかった」と混ぜない。原因を記録する。
4. **実行を記録する。**
   - CLI の版、要求したモデル名、取得できれば実際のモデル名、実行設定を保存する。
   - CLI の出力、コンテナ操作ログ、ATIF trajectory、Harbor の結果を保存する。
   - 入力・出力・キャッシュトークン、課金情報は CLI が報告する範囲で記録する。不明は不明とし、0 や推定料金で埋めない。
   - 金額、Copilot の利用点数、サブスクリプションの利用制限は別物として扱う。
5. **終了とタイムアウトを扱う。**
   - 子プロセス、MCP、ブリッジ、一時ディレクトリを後始末する。
   - タイムアウトでも取得済みのログ・使用量を残す。
   - 自分が起動していないプロセスや、ユーザーのセッションは削除しない。

## 共通部分の扱い

既存の MCP サーバーは変更せず再利用する。既存のブリッジを再利用できるか確認する。
並行作業中は共有コードの抽出や変更をしない。既存の内部クラスへの依存が必要なら、依存箇所を報告する。
必要な共通修正は、最後に統合担当がまとめて行う。

## 検証

まずモデルを呼ばずに、偽の CLI と偽のコンテナ環境で自動テストを作る。

- コマンド・設定が意図した CLI に渡る。
- コンテナ操作がブリッジを通り、ホストでは実行されない。
- 通常終了、非ゼロ終了、認証失敗、権限拒否、タイムアウトを区別できる。
- 出力制限、使用量の欠損、CLI 出力の異常を扱える。
- タイムアウト後にプロセスや一時ファイルが残らない。
- ツール制限は CLI の設定・実行ログから確認する。「モデルが他のツールは無いと言った」だけでは証拠にしない。

実モデルを呼ぶテストは利用枠を消費する。**別途ユーザーの承認を得るまで実行しない。**
承認後は既存 smoke タスク 1 回から始める。公開ベンチ全体やモデルの大量プローブは行わない。
実モデル未実施なら、その事実を明記する。

## 完了時の報告

- 変更したファイルと実行方法
- 実行したテストと結果
- ログイン・ツール制限の確認方法と未確認事項
- 記録できる使用量と記録できない使用量
- 共通ファイルに必要な変更案（実際には変更しない）
- 実モデルを実行した場合は、その回数と報告された使用量
